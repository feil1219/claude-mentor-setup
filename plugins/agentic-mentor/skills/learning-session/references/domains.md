# Learning domains

Six paths Michael tracks. Detailed curricula live in his learning project
(`~/Documents/Claude/Projects/learning/learning-paths/`); this file is the map,
so a session on another machine still knows the shape.

| Path | Scope | Note |
|---|---|---|
| `software-engineering` | Foundations: architecture, structures, systems | The base layer the others lean on |
| `agentic-se` | Agent-based development, tooling, harness design | His stated mastery goal |
| `generative-ai` | LLMs, prompting, RAG, evaluation | Mother domain for several others; moves fastest, so the vocabulary moves fastest too |
| `machine-learning` | Classical ML, training, evaluation | Underpins generative-ai and computer-vision |
| `computer-vision` | Perception, models, pipelines | Feeds robotics |
| `robotics` | Embodied systems, control, integration | Furthest from daily work |

Each path is structured as: North Star → map from foundational to state of the
art → key terms → sources → language notes → bridges to neighbouring paths.

**Emphasis across all six:** architectures, structures, systems — and the
professional vocabulary that goes with them. Every domain gets a glossary with
German and English terms, synonyms, idiomatic jargon and slang. The glossary is
not a reference to be filed; the terms are meant to be used actively in
conversation, and Michael corrected when he uses them unidiomatically.

**Selection rule:** one path active at a time. When Michael has not chosen one,
generative-ai is the recommended entry point — it is the parent domain for
several of the others, its vocabulary changes fastest (so it rewards active use
most), and it connects directly to his daily work with Claude.
